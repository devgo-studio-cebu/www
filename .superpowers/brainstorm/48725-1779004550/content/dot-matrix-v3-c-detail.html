Technical Animation Spec (animejs v4)

Phase 1: Pulse (0ms – 800ms)

3 dots centered on screen, opacity pulses 0.3 → 1 in sequence with anime.stagger(). "Loading" text types in.

Phase 2: Expansion (800ms – 1600ms)

Each dot drifts to a coarse grid position (e.g. 6×4 cells). New dots spawn from originals via anime({create}). Total ~15-20 dots. translateX/Y: [0, target], scale: [1, 0.6], opacity: stagger.

Phase 3: Multiplication (1600ms – 2400ms)

Dots continue splitting and drifting. Each dot fades toward its final position in the hero. Colors transition from accent (#5fcba6) → hero image colors. Count reaches ~50+.

Phase 4: Resolution Match (2400ms+)

Loading overlay fades. PixiJS hero canvas (already initialized behind) takes over. The scattered dots from loading seamlessly "become" the first visible particles of the hero grid. No hard cut.

Implementation Strategy

  • Loading Overlay: A fixed inset-0 z-50 div housing animejs-driven dot elements. No PixiJS dependency.
  • Hero Pre-Init: PixiJS app starts in the background during loading (opacity: 0, pointer-events: none). Once ready, loading overlay fades and hero takes over.
  • Color Bridge: Loading dots near the hero's center drift toward their corresponding pixi particle positions. Colors interpolate from #5fcba6 → hero pixel colors.
  • Real Load Sync: Could tie phase speed to actual progress (Phase 1 = 0-30% loaded, Phase 2 = 30-60%, Phase 3 = 60-90%). Final phase triggers on complete.
